# RAG Aliases Migration Plan

## Цель

Добавить в RAG-систему alias-based lifecycle (`champion` / `challenger`) для Qdrant коллекций,
чтобы сравнивать retrieval-архитектуры без полного релиза в production.

* продакшн по умолчанию использует `champion` alias
* `challenger` alias используется для тестирования новых конфигураций в production и оффлайн экспериментах
* promotion - "продвижение" какой-либо коллекции на уровень выше. Например, из `challenger` в `champion`, или из staging collection в какой-либо alias.
* при регулярных обновлениях RAG-данных (если происходит замена старой collection на новую, например для документации) новый индекс строится в staging collection, тестируется и затем продвигается на alias-ы. Продвижение из staging в alias-ы на данном этапе выполняется вручную.
* при регулярных обновлениях RAG-данных (если данные добавляются к существующему индексу, например для arxiv статей), новые данные добавляются ко всем collection-ам, привязанным к исходному датасету. В этом случае нет необходимости в staging collection, так как индекс строится инкрементально.
* такие параметры как `top_k`, `score_threshold`, `reranking` пока задаются глобально для всей RAG-конфигурации, а не per-alias. Эксперименты с этими параметрами выполняются через деплой новой production-конфигурации.
* нужно будет разделить понятия 'knowledge base' и 'collection'. Knowledge base должно использоваться в UI и соответствовать понятию 'dataset', collection + aliases должно использоваться в настройках API. Gateway получает от UI knowledge base. Для каждой knowledge base может существовать одна или более collections, каждая из которых может иметь 0, 1 или несколько alias-ов. Production всегда работает на 'champion' alias. Если 'champion' alias недоступен или не существует, то продакшн считает, что такая knowledge base недоступна, и возвращает ошибку (для избежания silent failures). Тестировочные скрипты могут передавать другой alias для одной и той же knowledge base. В процессе тестов аналогично: если указанный alias недоступен, тесты должны падать с ошибкой.
